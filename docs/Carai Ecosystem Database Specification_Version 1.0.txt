Global Standards

Every table includes:

id (UUID)

organization_id

created_at

updated_at

created_by

updated_by

deleted_at (soft delete where appropriate)

This ensures consistency across the entire platform.


---

Indexing Strategy

From day one, index:

organization_id

business_id

customer_id

conversation_id

created_at

status


These will be the most common query paths and will keep the application responsive as data grows.


---

Supabase & PostgreSQL Features

Since you've already committed to Supabase, I'd lean into PostgreSQL's strengths instead of treating it as a generic SQL database:

Row Level Security (RLS) for tenant isolation.

pgvector for embeddings and semantic search.

JSONB for flexible AI metadata, provider responses, and configuration.

Full-text search for documents and conversations.

LISTEN/NOTIFY (or Supabase Realtime) for live updates to dashboards and chats.

Generated columns where they simplify common queries.



---

Final Design Principle

The database should not know whether a request came from:

Carai AI Receptionist

Admin ESA

DevOS

Atelier

AI Sales

AI Marketing


It simply stores and serves data according to well-defined domains.

That way, every new product strengthens the same foundation instead of creating another isolated data silo.
